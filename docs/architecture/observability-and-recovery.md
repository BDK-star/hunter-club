# 可观测性、备份与恢复

## 服务目标

试运行阶段：

- 月度可用性目标：99.5%。
- 普通页面服务端响应时间：p95不超过500毫秒。
- 服务器错误率：低于1%。
- RPO：最多损失24小时数据。
- RTO：4小时内恢复基本浏览和登录。

这些是内部工程目标，不等同于免费平台对用户提供的SLA。

## 健康检查

- `/health/live`：进程能否响应，不访问依赖。
- `/health/ready`：检查数据库和关键配置，可使用严格超时。
- 外部监控单独检查首页、公开资料页和登录入口。
- 健康接口不返回版本秘密、数据库地址或内部异常。

## 日志

所有日志使用结构化字段：

- 时间、级别、环境和应用版本。
- 请求关联ID。
- 路由模板，不记录带隐私的完整URL。
- 模块、操作和稳定错误码。
- 经伪匿名化的用户ID，仅在确有排障需要时记录。
- 耗时和结果。

禁止记录：令牌、Cookie、验证码、连接串、私密投稿全文、举报证据正文和完整邮件地址。

## 指标

### 应用

- 请求量、p50/p95/p99延迟和5xx比例。
- Server Action与Route Handler失败率。
- 缓存命中和失效次数。
- 前端错误、LCP、INP和CLS。

### 数据库

- 连接池使用率、慢查询和事务冲突。
- 表与索引增长。
- 迁移版本和失败。
- 备份年龄。

### 业务

- 搜索零结果率和点击率。
- 投稿队列长度和审核耗时。
- 举报队列长度和超期案件。
- Outbox积压、重试和死信。
- 邮件发送成功、退信和重复抑制。

## 告警

只为可行动问题告警：

- 连续健康检查失败。
- 错误率或延迟持续越界。
- 数据库无法连接或连接池耗尽。
- Outbox持续积压。
- 备份超过允许年龄。
- 登录或权限变化出现异常峰值。

每条告警链接到运行手册，说明影响判断、止损、恢复和升级路径。

## 备份

- 每日数据库备份。
- 每周将加密备份复制到Supabase之外的独立存储。
- 媒体对象与媒体元数据分别备份，以哈希验证对应关系。
- 密钥与备份分开管理。
- 数据库迁移前创建额外恢复点。
- 备份保留周期必须覆盖隐私删除策略，不能无限保留已删除用户数据。

## 恢复演练

至少每季度：

1. 在隔离环境建立空数据库。
2. 恢复最近备份。
3. 运行当前迁移。
4. 核对抽样用户、角色、资料、文章修订、评论和测试结果。
5. 核对媒体文件数量、哈希和权利记录。
6. 验证登录、公开浏览、搜索和审核。
7. 记录实际RPO、RTO和缺陷。

“备份任务显示成功”不算恢复验证。

## 降级策略

- 认证不可用：保留公开只读浏览，禁用写操作。
- 邮件不可用：保留Outbox并延迟发送，不回滚已完成业务事务。
- 搜索不可用：退回数据库精确/前缀搜索或资料目录。
- 对象存储不可用：显示文字内容和媒体占位，不破坏文章。
- 装饰场景资源失败：显示静态酒吧和标准导航。
- 数据库不可用：返回明确维护状态，不展示可能过期的私人页面缓存。
