# ADR-0001：采用模块化单体

- 状态：Accepted
- 日期：2026-08-01

## 背景

项目预计由1至3名维护者运营，首年月活不超过1万，但需要涵盖内容、社区、测试、治理和叙事体验。微服务会提前引入跨服务认证、网络错误、分布式追踪、数据一致性和多套部署流程。

## 决策

将系统实现为一个可部署的Next.js应用和一个PostgreSQL数据库。代码按领域模块拆分，模块只能通过公开应用端口或领域事件协作，并各自拥有数据和规则。

## 后果

正面：

- 本地开发和部署简单。
- 跨模块强一致事务可直接使用PostgreSQL。
- 共享类型和重构成本低。
- 小团队能完整理解运行系统。

代价：

- 必须用静态规则和代码审查防止模块边界腐化。
- 一个部署故障可能影响整个应用。
- 扩容默认以整个应用为单位。

## 拆分触发条件

只有出现真实证据时考虑拆分，例如独立扩缩容、独立故障域、独立发布团队、资源类型冲突或单进程无法满足SLO。优先候选是搜索、通知和媒体处理，不预先承诺拆分日期。
