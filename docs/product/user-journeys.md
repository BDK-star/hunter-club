# 核心用户旅程

## 1. 首次访客进入

1. 访问酒吧门外页面。
2. 页面立即提供“登记猎人身份”和“作为旅客进入”。
3. 用户选择访客进入，不被迫注册。
4. 选择剧透等级；跳过时采用保守默认值。
5. 进入酒吧大厅，看到可点击NPC与标准导航。
6. 键盘、触摸和屏幕阅读器均可访问同一功能。

失败与降级：

- 场景图片失败时展示文字版酒吧和功能列表。
- JavaScript尚未完成加载时，核心链接仍可导航。
- 用户启用减少动态效果时跳过镜头动画。

## 2. 查找资料

1. 用户点击探险者NPC或直接进入资料库。
2. 搜索角色规范名、别名、日文名或罗马字。
3. 按内容类型、来源和剧透等级筛选。
4. 进入资料页，查看事实、来源与版本差异。
5. 通过实体关系进入念能力、组织或篇章。

验收重点：公开资料可被直接链接、搜索引擎抓取和分享；场景不是必经步骤。

## 3. 完成念能力测试

1. 用户通过酒保NPC进入测试说明。
2. 系统固定测试版本并开始答题。
3. 未完成尝试可短期恢复。
4. 完成后显示六维得分、主要倾向、次要倾向和解释。
5. 访客结果仅保存在本地；登录后可同步。
6. 分享卡片不包含原始答案或未授权素材。

验收重点：同一版本和答案必须得到相同结果；发布后不能原地修改计分规则。

## 4. 投稿或纠错

1. 登录会员从老板NPC、资料页或文章页进入投稿。
2. 选择新文章、资料修订或事实纠错。
3. 提交内容、来源、剧透等级和必要的权利声明。
4. 系统保存草稿并进行格式与权限校验。
5. 用户提交审核；编辑查看差异与来源。
6. 编辑批准、要求修改或拒绝，并记录理由。
7. 用户收到站内通知；必要时收到事务邮件。

验收重点：审核决定与发布必须在同一一致性边界内；重复提交不能生成多次发布。

## 5. 评论与举报

1. 登录会员在资料或文章的讨论主题下评论。
2. 评论可标记剧透并使用受限Markdown。
3. 其他会员可回复或举报。
4. 举报生成结构化案件和证据快照。
5. 版主处理并记录规则依据；高风险处罚要求复核。
6. 被处理用户可以申诉。

验收重点：被删除父评论保留占位；举报人与版主内部信息不得泄露。

## 6. 编辑审核

1. 编辑进入待审核队列。
2. 按风险、等待时间和内容类型筛选。
3. 比较当前发布版本与投稿修订。
4. 核对来源、正典状态、剧透等级和媒体权利。
5. 发布新版本或退回修改。
6. 必要时回退到先前已发布版本。

验收重点：管理员身份不允许绕过版本记录；数据库控制台不是日常编辑入口。

## 7. 开发者贡献

1. 阅读README、CONTEXT和相关ADR。
2. 在本地启动应用、数据库和测试环境。
3. 从短生命周期分支修改单一模块。
4. 提交Pull Request并获得预览环境。
5. 自动检查通过，代码所有者审核。
6. Squash合并至受保护的`main`。
7. 自动部署并执行生产冒烟检查。

验收重点：预览部署不得访问生产密钥或生产用户数据。
