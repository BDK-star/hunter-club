# 质量门槛

## 合并前必须通过

1. 格式和Lint。
2. TypeScript严格类型检查。
3. 模块依赖规则检查。
4. 领域单元测试。
5. PostgreSQL集成测试。
6. API与权限契约测试。
7. 核心端到端测试。
8. 关键场景视觉回归。
9. 自动无障碍检查。
10. 依赖漏洞和密钥扫描。
11. 生产构建。
12. 资源体积预算。
13. 从上一正式结构升级的迁移测试。

失败检查不得以“先合并再修”绕过。例外必须由代码所有者记录理由、风险、有效期和补救Issue。

## 测试分层

### 领域单元测试

高覆盖目标用于：

- 权限和角色约束。
- 内容发布状态机。
- 正典与剧透过滤。
- 念能力测试计分。
- 标签合并与别名解析。
- 举报与申诉状态机。
- 数据保留规则。

### 集成测试

使用真实PostgreSQL验证：

- 唯一约束、外键、事务和并发。
- ORM映射与原生索引。
- Outbox原子写入和幂等领取。
- 从上一版本迁移。
- 删除、匿名化和保留任务。

### 端到端测试

至少覆盖：

- 访客推门进入和直接URL浏览。
- 登录、退出和会话撤销。
- 查找资料与剧透过滤。
- 完成念能力测试并保存结果。
- 评论、回复和举报。
- 投稿、要求修改、批准和发布。
- 编辑回退内容。
- 管理员分配角色并触发二次认证。

## 场景测试

- 桌面、平板、手机视口。
- 键盘导航和焦点顺序。
- 屏幕阅读器可理解的NPC名称与功能。
- `prefers-reduced-motion`。
- 静态降级模式。
- 图片、音频或动画资源失败。
- 慢速网络和低端CPU模拟。

阶段2通过`pnpm test:e2e`将当前可运行范围纳入浏览器门禁：桌面、平板、手机视觉基线；键盘与触摸核心旅程；Axe自动无障碍扫描；JavaScript关闭时的标准URL降级；减少动画；首屏资源、LCP、CLS和交互实验室预算。基线只能通过`pnpm test:e2e:update`显式更新，更新后必须人工检查图片并登记媒体资产。

## 性能预算

| 指标 | 门槛 |
|---|---|
| LCP | p75 ≤ 2.5秒，移动与桌面分开 |
| INP | p75 ≤ 200毫秒 |
| CLS | ≤ 0.1 |
| 首屏关键压缩资源 | ≤ 1.2 MB |
| 首次加载JavaScript | gzip后≤ 250 KB |
| 首屏字体 | ≤ 150 KB |
| 完整酒吧场景资源 | ≤ 4 MB，非关键资源延迟加载 |

资源体积是初始工程预算，可根据真实用户数据通过ADR调整；不能在单个Pull Request中随意放宽。

加载顺序必须是：基础HTML与导航 → 低清场景 → 可点击NPC → 高清图层 → 动画与音频。

## 安全验收

- 每个敏感用例至少有“允许”和“拒绝”测试。
- 水平越权测试尝试访问其他用户草稿、通知和测试记录。
- 垂直越权测试尝试调用编辑、版主和管理员动作。
- 富文本、链接和上传执行恶意输入测试。
- 预览环境验证无法读取生产秘密。
- 错误页验证不泄露堆栈和SQL。

## 部署后冒烟检查

- 首页和静态降级可访问。
- 公开资料页可直接打开。
- 登录入口工作。
- 数据库和对象存储连接正常。
- 搜索返回种子数据。
- 测试定义可加载。
- 健康检查返回正确状态。

冒烟失败自动标记发布失败并执行既定回退流程。
