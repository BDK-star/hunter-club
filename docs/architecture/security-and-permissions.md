# 安全与权限

## 安全目标

- 公开阅读不泄露草稿、隐藏剧透、举报证据或用户隐私。
- 所有写操作在服务端认证、授权、校验并审计。
- 高权限账号被盗时限制影响范围。
- 外部服务或媒体处理失败时不破坏核心内容一致性。

## 身份模型

- 网站拥有稳定`User`实体。
- 邮箱验证码、GitHub和未来OIDC身份存入独立`Identity`。
- 一个用户可绑定多个身份，合并需要重新认证和冲突检查。
- 服务端会话通过`HttpOnly`、`Secure`、适当`SameSite` Cookie传递。
- 访问令牌不得存入浏览器`localStorage`。
- 编辑、版主和管理员必须启用通行密钥或独立第二因素。
- 更改邮箱、绑定身份、删除账号和提升权限要求近期重新认证。

## 角色

| 角色 | 主要权限 |
|---|---|
| 游客 | 浏览公开内容、访客测试 |
| 会员 | 收藏、评论、投稿、纠错、举报 |
| 贡献者 | 创建结构化资料草稿和修订 |
| 编辑 | 审核、发布、归档、回退内容 |
| 版主 | 处理评论、举报、处罚和申诉 |
| 管理员 | 管理角色、关键配置和高风险操作 |

角色只授予能力，不自动拥有所有资源。授权还要检查：内容状态、资源归属、案件冲突、二次认证状态和剧透范围。

## 权限矩阵摘要

| 操作 | 游客 | 会员 | 贡献者 | 编辑 | 版主 | 管理员 |
|---|---:|---:|---:|---:|---:|---:|
| 浏览公开内容 | 是 | 是 | 是 | 是 | 是 | 是 |
| 收藏、评论、举报 | 否 | 是 | 是 | 是 | 是 | 是 |
| 提交普通投稿 | 否 | 是 | 是 | 是 | 是 | 是 |
| 提交资料修订 | 否 | 建议/纠错 | 是 | 是 | 是 | 是 |
| 审核与发布 | 否 | 否 | 否 | 是 | 否 | 是 |
| 处理普通举报 | 否 | 否 | 否 | 否 | 是 | 是 |
| 分配高权限角色 | 否 | 否 | 否 | 否 | 否 | 是，需复核 |

管理员仍不得绕过修订、审核和审计记录直接发布内容。

## 输入与输出防护

- 所有外部输入使用共享模式定义在边界校验。
- Markdown采用允许列表渲染，禁止原始HTML和危险URL协议。
- 上传按文件头解码验证，不信任扩展名或客户端MIME。
- 外部URL抓取默认禁止；确需实现时使用目标允许列表、DNS/IP检查、大小和超时限制，防止SSRF。
- 输出使用框架转义，安全富文本经过服务端净化。
- 错误响应使用稳定错误码，不返回堆栈、SQL或供应商细节。

## Web防护

- 配置严格CSP并逐步移除`unsafe-inline`。
- 设置HSTS、`X-Content-Type-Options`、合理Referrer Policy和Permissions Policy。
- Cookie认证写操作使用框架支持的CSRF防护、同源检查或显式令牌。
- 登录、验证码、评论、搜索、举报和投稿分别限流。
- 限流键组合账号、匿名会话和经最小化处理的网络信号，避免单纯按IP误伤共享网络。
- 外部链接添加适当`rel`属性，用户链接不传递信任。

## 剧透访问控制

剧透过滤不是纯CSS隐藏：

- 查询层先过滤不可见事实与搜索文档。
- 页面元数据、结构化数据、预取响应和缓存键都包含适用剧透边界。
- 评论剧透正文默认不进入通知邮件。
- 管理与审核角色可在明确提示后查看必要内容。

## 审计

必须审计：

- 登录方式绑定与解绑。
- 会话撤销和高风险认证事件。
- 角色与权限变化。
- 发布、归档和回退。
- 举报决定、处罚和申诉。
- 媒体隔离与恢复。
- 数据导出和账号删除。

审计日志追加写入；普通后台无删除入口。日志记录操作者、动作、目标、时间、请求关联ID和理由，但不复制完整敏感正文。

## 密钥管理

- `.env.example`只列变量名和用途，不放真实值。
- 本地、预览和生产使用不同凭据。
- 预览部署绝不接收生产数据库、服务角色或邮件生产密钥。
- 密钥只存在部署平台或安全凭据库，GitHub只保存部署所需的最小秘密。
- 建立轮换与吊销步骤，泄露时能在不改代码的情况下更换。

## 安全事件最低响应

1. 确认影响并冻结相关凭据或功能。
2. 保存必要审计证据。
3. 轮换密钥并撤销会话。
4. 修复漏洞并添加回归测试。
5. 评估数据范围和通知义务。
6. 发布不泄露攻击细节的用户说明。
7. 复盘并更新威胁模型和运行手册。
