# MVP交付路线

本路线按依赖和验收条件组织，不给出未经团队容量校准的日期估算。每一阶段必须形成可演示、可测试的纵向结果。

## 阶段0：仓库与架构治理

交付：

- 初始化Git和GitHub仓库。
- 添加Apache-2.0代码许可证、NOTICE、资产许可清单。
- 添加贡献指南、行为准则、安全政策、Issue与Pull Request模板。
- 配置受保护`main`、CODEOWNERS、DCO和基础CI。
- 将ADR与模块依赖规则设为评审依据。

退出条件：新开发者能识别项目状态、许可边界和变更流程。

## 阶段1：可运行骨架

交付：

- Next.js、TypeScript严格模式和样式基础。
- PostgreSQL、迁移工具和本地开发环境。
- 应用配置校验、稳定错误格式、请求关联ID。
- 模块目录和边界自动检查。
- 健康检查、结构化日志和基础测试。
- Vercel预览部署与Supabase开发项目连接。

退出条件：空功能应用可在本地、预览和生产环境一致构建，预览无生产秘密。

## 阶段2：酒吧入口纵向切片

交付：

- 门外与大厅的低保真原创占位视觉。
- Scene Manifest、NPC、热点、对话图和能力注册表。
- 访客进入、剧透偏好、标准导航与直接URL。
- 移动端、键盘、减少动画和静态降级。
- 视觉回归和性能预算检查。

退出条件：用户不登录也能从酒吧进入一个真实内容页面；资源失败时仍可导航。

## 阶段3：身份、资料与出版闭环

交付：

- 邮箱验证码、GitHub身份、服务端会话和内部User映射。
- 角色与权限基础，高权限二次认证。
- 四类资料实体、来源、事实、翻译、别名和实体关系。
- 专题文章、不可变修订、发布和回退。
- 编辑后台和审核差异视图。
- 基于PostgreSQL的搜索投影与筛选。

退出条件：编辑能从草稿发布一项带来源资料，访客能通过搜索和直接URL查看正确剧透范围的版本。

## 阶段4：念能力测试

交付：

- 版本化测试定义、问题、选项、计分规则和解释。
- 访客本地结果与登录同步。
- 历史结果和隐私保留任务。
- 酒保NPC能力映射。

退出条件：同一版本与答案结果确定，升级测试不会改变历史尝试。

## 阶段5：社区贡献闭环

交付：

- 收藏、两级评论、受限Markdown和剧透折叠。
- 投稿、纠错、审核、退回和发布。
- 受控分类、标签建议、合并和别名。
- 站内通知、Outbox和必要事务邮件。
- 老板、探险者等NPC能力映射。

退出条件：会员能完成“投稿 → 编辑审核 → 发布 → 通知”且任务重试不产生重复内容或邮件。

## 阶段6：治理、权利与隐私

交付：

- 举报案件、证据快照、处罚、复核和申诉。
- 媒体权利记录、隔离和恢复。
- 用户数据导出、账号删除和保留期限任务。
- 审计日志和权限回归测试。
- 赏金猎人NPC能力映射。

退出条件：普通版主无法处理自身案件；删除账号后身份数据按合同清除，公开修订历史正确匿名化。

## 阶段7：试运行加固

交付：

- Core Web Vitals实测与资源优化。
- 外部可用性检查、错误告警和运行手册。
- 独立加密备份与完整恢复演练。
- 安全审查、依赖扫描和滥用限流。
- 内容种子、社区规则、隐私说明和版权投诉入口。
- 生产冒烟、回退和发布记录。

退出条件：达到质量门槛；恢复演练满足RPO 24小时和RTO 4小时；首版范围内不存在已知高风险阻断问题。

## 试运行后再决策

只有真实数据支持时评估：

- 独立搜索引擎。
- 更多场景和NPC。
- 浏览器推送。
- AI受约束问答。
- 更多资料类型与语言。
- 独立任务执行器或服务拆分。

## 明确延期

自由论坛、私信、聊天室、全3D、任意图片上传、复杂推荐、积分商城和移动App不进入MVP。任何将其提前的提案必须说明替换掉哪个已承诺交付物以及新增的审核与运维成本。
