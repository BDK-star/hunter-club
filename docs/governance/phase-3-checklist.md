# 阶段3完成清单

阶段3交付身份、资料与出版闭环。公开阅读继续不要求登录；所有写入必须通过服务端身份、资源权限、内容状态和适用的二次认证检查。

## 3A：身份与权限基础

- [x] 内部用户、外部身份、服务端会话、角色、权限和安全事件具有版本化数据库迁移。
- [x] 邮箱验证码与GitHub身份只映射内部用户，不进入业务外键。
- [x] 高权限角色在授权策略中强制`aal2`，前端可见性不作为授权。
- [x] 会话只持有令牌摘要，支持到期和主动撤销。
- [x] 身份约束、权限策略和迁移进入自动测试。
- [ ] 邮箱验证码与GitHub供应商适配器完成登录、回调、绑定和注销流程。
- [ ] 服务端会话通过安全Cookie签发、轮换并在受保护写入前解析。

## 3B：资料与来源

- [x] 角色、念能力、组织、篇章四类资料实体可创建草稿。
- [x] 名称、翻译、别名、事实声明和实体关系具有明确所有权与约束。
- [x] 来源与引用定位可复用，事实声明必须关联来源。
- [x] 正典状态、剧透等级和最后核对时间进入查询合同。

## 3C：出版闭环

- [x] 专题文章和资料实体使用不可变修订。
- [x] 审核记录发布者、决定、理由和目标修订。
- [ ] 发布与回退只移动已验证指针，不覆盖历史修订。
- [ ] 编辑后台展示草稿与当前发布版本的差异。

## 3D：搜索与公开阅读

- [x] PostgreSQL搜索投影可由内容真相源重建。
- [x] 名称、别名、内容类型、正典状态和剧透等级可筛选。
- [ ] 搜索和直接URL只返回已发布且符合剧透边界的修订。
- [x] 零结果和匿名查询指标不记录可识别正文或身份数据。

## 阶段退出条件

- [ ] 编辑能从草稿发布一项带来源资料。
- [ ] 访客能通过搜索和直接URL查看正确剧透范围的版本。
- [ ] 本地质量门、Pull Request门禁、Vercel Preview和生产冒烟全部通过。

阶段3不得提前实现社区评论、收藏、投稿闭环或念能力测试计分。身份供应商故障不得阻断公开阅读。

## 当前实现证据

本节只登记实际通过的迁移、测试、Pull Request和部署证据；未完成项不得以设计文档代替实现。

- 阶段3首个切片新增8张身份表和3个受约束枚举；外部身份以`provider + provider_subject`唯一映射内部用户，业务模块只引用`users.id`。邮箱验证码身份必须包含规范化邮箱和验证时间。
- 会话表只保存64位小写十六进制SHA-256摘要，数据库限制最长30天、到期时间晚于创建时间并支持`revoked_at`；应用层使用常量时间摘要比较。
- Supabase试运行适配器使用当前SSR客户端、每请求实例、PKCE GitHub回调和`getClaims()`服务端验签；邮箱六位验证码和GitHub身份统一映射内部用户。首次登录只授予`member`，应用另发7天随机会话Cookie并支持数据库撤销。供应商控制台、SMTP、限流、TOTP和浏览器验收尚未完成，故3A操作项保持未完成。
- 5个角色、7项能力和17条授权关系由迁移显式种子化。编辑、版主、管理员授予的能力必须在`aal2`会话下执行，停用或删除账号始终拒绝。
- 隔离PGlite验证空库按顺序应用全部版本化迁移，并覆盖角色权限种子、外部身份唯一性、会话摘要与期限、删除状态一致性。单元测试覆盖普通会员、越权、高权限二次认证、外部身份映射和会话令牌摘要。供应商控制台、Cookie轮换和真实浏览器验收尚未完成，故操作项保持未完成。
- 资料切片新增`catalog_entities`、翻译、别名、来源、来源定位、事实声明、事实来源、实体关系、关系来源和Slug历史10张表；首版实体种类由数据库枚举限制为角色、念能力、组织和篇章。
- 资料发布合同要求至少一项翻译，禁止重复语言；关键事实和实体关系必须有来源、非`unverified`正典状态和非未来核对时间。`safe → anime → manga`作为有序剧透查询边界，查询层可在返回正文前过滤。
- 数据库回归覆盖唯一Slug、唯一主翻译、规范化别名去重、来源定位复用、事实与来源联结、自关系和未来核对时间拒绝。
- 出版切片新增专题文章、通用内容修订、审核决定、文章/资料发布指针与发布事件6张表。数据库触发器使修订、审核和事件成为只追加记录，复合外键阻止指针跨目标串线；应用服务在读取受保护状态前校验权限和`aal2`，并只接受最新审核结论为批准的修订。真实数据库事务适配器尚未完成，因此发布指针闭环仍保持未完成。
- 搜索切片新增`search_documents`可重建投影和`search_query_metrics`匿名指标表；端口不暴露PostgreSQL实现。名称、去重别名与正文使用`pg_trgm`索引，集成回归覆盖内容类型、正典状态和有序剧透边界。查询指标只保存密钥HMAC指纹、长度、计数和非识别筛选，不保存查询正文或用户标识。
- 当前空库迁移总数为5项；迁移集成测试已启用与生产PostgreSQL一致的`pg_trgm`扩展包。
- 2026-08-12阶段3首批全仓质量门通过：格式、Lint、严格类型、75个模块架构边界、体验合同、19个单元测试文件共46项、5个隔离数据库测试文件共21项，以及Next.js 16.3生产构建均成功。浏览器、Pull Request与部署门禁尚未执行。
